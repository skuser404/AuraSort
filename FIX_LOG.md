## 1.1.2: Windows "0 files", Android move/copy, installer

| # | Report | Verdict | Root cause and evidence |
|---|---|---|---|
| A | Windows, v1.1.1: Deep Scan of C: and D: estimated "About 7,629 files", then "0 files, 1 folders skipped" | **Confirmed, fixed** | Python 3.12+ on Windows returns the 64-bit volume serial as `st_dev`. At or above 2**63 SQLite raises `OverflowError: Python int too large to convert to SQLite INTEGER` when the first folder is stored (`core/scanner.py:301` walk_drive, `core/index_db.py:665` _ensure_dir), so every folder was skipped as "error". The estimate does not use SQLite, so it saw the files. Before: `tests/test_volume_serial.py` `AssertionError: 0 != 5 : skipped: {'error': 1}` and the log line "a folder could not be stored and was skipped (OverflowError)". After: `dev_key()` (`core/platform_utils.py:96`) folds the value into the signed range, `Ran 2 tests ... OK`. The CI failures on Windows 3.12-3.14 (and not 3.10) in run 43019470363 had the same cause. This PC's serial has the top bit clear, which is why it was never seen here |
| A2 | Suspects: drive root `C:` (cwd-relative), protection on the root, PermissionError on the root, estimator vs scanner, stale results | Not the cause; hardened anyway | `tests/test_paths.py`: `C:`, `C:\`, `c:/`, `\\?\C:\`, `D:`, `/`, `/storage/emulated/0`, spaces, non-ASCII. Before: `'\\\\?\\c:\\' != 'c:\\'` (the long prefix slipped past protection checks) and `..` kept. Estimator vs scanner: found >= 0.9 x estimate, also with a 64-bit serial. Started from `C:\Windows\System32`: the server now changes to the home folder (`server.py` start_folder); quick scan found 3 of 3 |
| B | Android: Move/Copy do not work | **Confirmed, fixed** | Android shared storage (FUSE) refuses `os.link` and `shutil.copystat` with EPERM. `core/copier.py:186` used a hard link with no fallback on POSIX and `:228` let copystat fail the copy. Before: `tests/test_android_move.py` `5 != 0 : ['IMG_0002.jpg: [Errno 1] Operation not permitted', ...]` for copy, name clash and cross-storage move, and the default destination was inside the Termux home. After: rename fallback, dates best-effort, destination on shared storage (`core/platform_utils.py:146`), `Ran 5 tests ... OK` (copy, move + undo, cross-storage move, clash keep-both, destination) |
| C | Installer: `irm ... \| iex` | **Confirmed, fixed (three bugs)** | Reproduced with Windows PowerShell 5.1.19041 from `C:\Windows\System32`, with the file served as GitHub serves it. (1) The UTF-8 BOM: `ERROR: At line:5 char:6 ... Unexpected token` for both `text/plain; charset=utf-8` (raw) and `application/octet-stream` (release asset). (2) `$PSCmdlet` is null under iex: `ShouldProcess ERROR: You cannot call a method on a null-valued expression.` (3) `exit` closed the window: the line after `iex` never ran. Fix: no BOM (`tests/test_installers.py`), and under iex the installer runs itself with `-File` in a child PowerShell (`scripts/install.ps1:29`). After: `Self-test passed: found 6 files.` / `The installer finished (exit code 0).` / `WINDOW-STILL-OPEN 0` |
| C2 | Release URL 404 | **Confirmed** (no release is published) | `curl -sSI .../releases/latest/download/install.ps1` gives 404; the README now uses `raw.githubusercontent.com/skuser404/AuraSort/main/scripts/install.ps1` (200), and without a release the installers fall back to `archive/refs/heads/main.zip` (302 then 200, `application/zip`) |
